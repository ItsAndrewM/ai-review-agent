# The bot's name from BOT_LOGIN Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every name a person, repository or GitHub sees comes from `BOT_LOGIN`, and a committed `staging` deploy, `andabot-staging`, reviews only when tagged.

**Architecture:** A small pure module `src/names.ts` turns a login into each name. The fixed constants go away, so the typechecker lists every call site, and each one takes the login it already has nearby (`this.botLogin()` in the object, `env.BOT_LOGIN` in the sandbox). A new var `AUTO_REVIEW` feeds the config defaults. `wrangler.jsonc` gains `env.staging`, and a test keeps its vars in step with production's.

**Tech Stack:** TypeScript on Cloudflare Workers, TypeBox, vitest (node environment), wrangler 4.

**Spec:** `docs/superpowers/specs/2026-11-01-bot-name-design.md`

## Global Constraints

- `BOT_LOGIN=andabot` gives exactly today's strings: `.andabot.yaml`, `<!-- andabot:summary -->`, `<!-- andabot:paused -->`, `<!-- andabot:closes -->`, `<!-- andabot:closes-end -->`, `andabot:review-budget-refused`, user-agent `andabot`, scripts `andabot-run` and the others.
- Leave Durable Object class names, log event names, Pi extension names (`"andabot"` in `src/review/tools.ts`, `VERIFY_EXTENSION`), the `AndabotConfig` type name and `tools/recall`'s `BOT_LOGIN` alone.
- Lint, from `CLAUDE.md`: no comments of any kind (JSDoc included), no type assertions but `as const`, complexity at most 10, no `unknown`/`object` params, no `typeof`, no `vi.mock`, no disable comments.
- `pnpm check` passes at the end of every task. `pnpm format` before each commit.
- Pure modules don't read `env`. They take `botLogin: string`.
- `wrangler.jsonc` keeps its comments, which say why. Staging's copy of the vars carries none.

## Review Focus

1. A summary comment andabot posted before the deploy (body starting `<!-- andabot:summary -->`) is still found and edited in place. Task 1 pins the literal.
2. A login that is a prefix of another (`andabot` and `andabot-staging`): andabot's finder must not take staging's summary comment, closes block or paused line, and the reverse. Task 1 tests it.
3. `@andabot-staging review` must not start an andabot review, and `@andabot-staging` must reach staging. Task 1 adds route tests.
4. `AUTO_REVIEW` unset (old `.dev.vars`, tests) behaves as `"true"`. Task 2 tests it.
5. On staging, an invalid or unreadable config file falls back to `auto: false`, not `true`. Task 2 tests it.
