# Skills for andabot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pin andabot's review procedure as bundled Agent Skills the host activates, make findings carry a host-validated basis, anchor and quote, add the spec axis, and measure the effect on a planted-bug pull request before and after each slice.

**Architecture:** Markdown skills under `skills/` are bundled into the Worker as text, parsed into an Agents SDK skill manifest, and offered through the `skills()` extension for `read_skill_resource`. The host renders the review skill into the root conversation's `instructions` before each review and carries the answer skill in a question's user turn. Slice 2 rewrites the submit loop: numbered patch lines, quote verification, basis, coverage, merge danger, linked issues, and an approval gate.

**Tech Stack:** Cloudflare Workers and Durable Objects, `@earendil-works/pi-durable` 1.3.0, `agents` 0.28.1 (`agents/skills`, `agents/harness/pi`), TypeBox, vitest, wrangler 4.151.1.

**Spec:** `docs/superpowers/specs/2026-10-17-skills-design.md`

## Global Constraints

- `pnpm check` passes before every commit: oxlint and oxfmt (120 columns, no semicolons, sorted imports; run `pnpm format` first), `tsc` for `tsconfig.json` and `tsconfig.node.json`, vitest.
- `CLAUDE.md` rules: no comments in code (a reason goes in a name, a test title or `docs/design.md`); every GitHub response parsed with a TypeBox schema and `Value.Check`; no type assertions except `as const`; complexity at most 10 per function; no `vi.mock`, so a dependency is replaced through a real interface; no `unknown` parameters or returns except a caught error's `cause`; no `typeof`; no `...(cond ? {...} : {})`.
- `@earendil-works/pi-durable` stays 1.3.0 and `agents` stays 0.28.1.
- The review skill body is under 120 lines; references load on demand.
- Anchoring is described once, in the `submit_review` schema; the skill points at it.
- Branches: `feature/<title>.GH-<issue>`. PR descriptions say `Closes #<n>` and that merging deploys nothing; `pnpm run deploy` deploys by hand.
- The planted-bug pull request never links #2 and its branch name carries no issue number, so the answer key never reaches the reviewer.
- Commit messages read like the repo's: one descriptive sentence, no conventional-commit prefix.

## Review Focus

1. A pull request description that tells the reviewer to approve: the prompt marks description, diff and linked issues as material under review, never instructions. Test in Task 16.
2. A quote whose text appears on two lines of the same file: the host rejects the finding instead of guessing. Test in Task 13.
3. A linked `#n` that is a pull request, not an issue: skipped, never rendered as a spec. Test in Task 16.
4. A generated file in the diff: not required in the walkthrough; a binary file with no patch still is. Tests in Tasks 12 and 14.
5. A blocking finding rejected on the final submission: the review posts as REQUEST_CHANGES, never APPROVE. Test in Task 15.

### Task 5: Parse skill files into a manifest

**Files:**
- Create: `src/review/skills.ts`
- Test: `test/skills.test.ts`

**Interfaces:**
- Consumes: `parseSkillMarkdown`, `fromManifest`, `SkillManifest`, `SkillContent` from `agents/skills`.
- Produces:
  - `interface SkillFile { readonly path: string; readonly content: string }` (path relative to `skills/`, such as `review/SKILL.md`).
  - `fingerprintOf(files: readonly SkillFile[]): Promise<string>`: lowercase hex SHA-256 over `${path}\n${content}\n` for each file sorted by path.
  - `buildSkillManifest(files: readonly SkillFile[], fingerprint: string): SkillManifest`: `id: "builtin"`; one entry per top-level directory with a `SKILL.md`; `version` from `metadata.version`; resources are the directory's other files, `kind: "reference"` under `references/`, else `"file"`, `encoding: "text"`, `size` in UTF-8 bytes; throws `Error("skills/<dir>/SKILL.md: invalid frontmatter")` when `parseSkillMarkdown` returns null.
  - `renderActivatedSkill(skill: SkillContent): string`: the exact text `activate_skill` would return.

- [ ] **Step 1: Write the failing tests**

```ts
import { readdirSync, readFileSync, statSync } from "node:fs"
import { join, relative } from "node:path"
import { describe, expect, it } from "vitest"
import { buildSkillManifest, fingerprintOf, renderActivatedSkill, type SkillFile } from "../src/review/skills.ts"

const ROOT = new URL("../skills/", import.meta.url).pathname
const walk = (dir: string): string[] =>
  readdirSync(dir).flatMap((name) => {
    const full = join(dir, name)
    return statSync(full).isDirectory() ? walk(full) : [full]
  })
const files: SkillFile[] = walk(ROOT).map((full) => ({ path: relative(ROOT, full), content: readFileSync(full, "utf8") }))

describe("buildSkillManifest", () => {
  it("lists review and answer with their frontmatter and the review references", () => {
    const manifest = buildSkillManifest(files, "abc")
    expect(manifest.id).toBe("builtin")
    expect(manifest.skills.map((s) => s.name).sort()).toEqual(["answer", "review"])
    const review = manifest.skills.find((s) => s.name === "review")
    expect(review?.version).toBe("1")
    expect(review?.resources?.map((r) => r.path).sort()).toEqual([
      "CREDITS.md",
      "references/merge-danger.md",
      "references/severity.md",
      "references/smells.md",
      "references/tests.md",
    ])
    expect(review?.resources?.find((r) => r.path === "CREDITS.md")?.kind).toBe("file")
    expect(review?.resources?.find((r) => r.path === "references/smells.md")?.kind).toBe("reference")
  })

  it("keeps the review body under 120 lines and every description under 1024 characters", () => {
    const manifest = buildSkillManifest(files, "abc")
    for (const skill of manifest.skills) {
      expect(skill.description.length).toBeLessThan(1024)
      expect(skill.name).toMatch(/^[a-z0-9]+(-[a-z0-9]+)*$/)
    }
    expect(manifest.skills.find((s) => s.name === "review")?.body.split("\n").length).toBeLessThan(120)
  })

  it("refuses a skill without a description", () => {
    expect(() => buildSkillManifest([{ path: "x/SKILL.md", content: "---\nname: x\n---\nbody" }], "f")).toThrow(
      "skills/x/SKILL.md: invalid frontmatter",
    )
  })
})

describe("fingerprintOf", () => {
  it("is 64 hex characters, stable, and changes with any byte", async () => {
    const a = await fingerprintOf(files)
    expect(a).toMatch(/^[0-9a-f]{64}$/)
    expect(await fingerprintOf(files)).toBe(a)
    const edited = files.map((f, i) => (i === 0 ? { ...f, content: `${f.content} ` } : f))
    expect(await fingerprintOf(edited)).not.toBe(a)
  })
})

describe("renderActivatedSkill", () => {
  it("wraps the body in skill_content with the resource list", () => {
    const text = renderActivatedSkill({
      name: "review",
      description: "d",
      version: "1",
      body: "Steps.",
      resources: [{ path: "references/severity.md", kind: "reference", encoding: "text", size: 12 }],
    })
    expect(text).toBe(
      [
        '<skill_content name="review" version="1">',
        "Steps.",
        "<skill_resources>",
        '  <file kind="reference" encoding="text" size="12">references/severity.md</file>',
        "</skill_resources>",
        "</skill_content>",
        "",
        "Bundled resources:",
        "- references/severity.md (reference, text, 12 bytes)",
      ].join("\n"),
    )
  })
})
```
