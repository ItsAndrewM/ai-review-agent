# The summary, resolve, pause and resume commands Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** andabot answers `@andabot summary`, `resolve`, `pause` and `resume`: a fresh summary without a review, a one-step override of its threads, and a pause on its own reviews and approvals, each confirmed where it was asked.

**Architecture:** The decisions are pure functions in new modules: `src/review/pause.ts` (the pause gate, the summary's paused line, what `resume` does next), `src/review/resolve.ts` (which threads, the reply), and `src/review/summary.ts` (the summary's parsing, stored record, verdict line and replies). `src/review/approval.ts` gains the new triggers, the evaluation's outcome, and what each review's summary showed. The summary run is a model pass in a Pi session of its own, configured with no tools, its answer held to JSON by the provider wrapper. `src/pull-request.ts` grows only by the handlers that apply them.

**Tech Stack:** TypeScript on Cloudflare Workers and Durable Objects, `agents` 0.28.1's `PiHarness` over `@earendil-works/pi-durable` 1.3.0, TypeBox, vitest, the GitHub REST and GraphQL APIs.

**Spec:** `docs/superpowers/specs/2026-10-21-commands-design.md`

## Global Constraints

- `pnpm format && pnpm check` passes before every commit: oxlint, oxfmt, both `tsc` configs and vitest. The baseline is 413 tests passing.
- `CLAUDE.md` rules apply:
  - no comments of any kind, JSDoc included;
  - no type assertions except `as const`;
  - every stored record (`pausedBy`, `summarizing`, `summarySession`, the extended `lastReview`) and the model's summary answer is parsed with TypeBox and `Value.Check`;
  - complexity at most 10 per function: split a function by what it decides;
  - the anti-slop rules, including no `...(cond ? {...} : {})` spread, no `typeof`, no `unknown` parameters except a caught error's;
  - no `vi.mock`.
- `tsconfig.json` has `exactOptionalPropertyTypes`: an optional field is omitted, never set to `undefined`. Build optional fields with a ternary between two objects, as `buildScope` does.
- Design reasons go in `docs/design.md`, never in code.
- No new runtime dependency and no new App permission.
- Commit messages are one descriptive sentence with no conventional-commit prefix.
- The PR body says "Closes #27" only once the live check in Task 10 has passed; otherwise "Part of #27", with no closing keyword before `#27` anywhere in it.
- Every reply, help line and comment line in this plan is exact copy: tests assert it verbatim.

## Review Focus

1. **A summary comment that isn't andabot's, or already carries the paused line.** `withPausedLine` leaves a body without `SUMMARY_MARKER` alone and replaces an earlier paused line rather than adding a second. Tests in Task 2.
2. **A command typed with odd case or spacing, or with words after it.** `@AndaBot RESOLVE` and `@andabot  pause  ` are commands; `@andabot pause please` is a question. Tests in Task 1.
3. **A summary answer wrapped in a `json` fence or prose, or with an empty walkthrough.** The first two parse; an empty walkthrough is unusable, so nothing is written. Tests in Task 6.
4. **`resolve` with none of andabot's threads open, or a thread whose author GitHub reports as `null`** (a deleted account). The first replies "None of my threads is open." and still says what approval does next; the second is never andabot's. Tests in Task 4.
5. **`resume` on a head the last push skipped as "No changes to review".** That head is the reviewed head with no `posted:<sha>` record. It counts as reviewed, so `resume` evaluates instead of starting a review. Test in Task 2.
