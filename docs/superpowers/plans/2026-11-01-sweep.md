# Sweep for Missed Heads Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A 15-minute Cron Trigger hands every open pull request head andabot has no record of to its object, which reviews it, restarts a dead review once, or answers from storage without calling GitHub.

**Architecture:** `src/sweep.ts` lists installations, repositories and open pull requests through three new `GitHubClient` methods and hands each pull request to its object's new `sweep` RPC. The object's choice is a pure function, `decideSweep` in `src/review/sweep-decision.ts`, over what it has stored; `pull-request.ts` wires it in, writes the new `decided` record at every exit that releases a head without posting, and marks sweep-started runs so the footer says so.

**Tech Stack:** TypeScript, Cloudflare Workers (Cron Triggers, Durable Object RPC), TypeBox, vitest, oxlint/oxfmt.

**Spec:** `docs/superpowers/specs/2026-11-01-hardening-design.md`, section "Slice 1, #189".

## Global Constraints

- Cron `*/15 * * * *`; window: `updated_at` within 1 day; floor: `updated_at` at least 5 minutes old.
- No cap on reviews per sweep (Andrew's ruling; #186).
- Delivery id `sweep:<sha>`; restart operation id `review:sweep:<sha>:restart`.
- Stuck threshold 30 minutes from `pending.started`.
- Footer copy, exact: "Started by the 15-minute sweep: no webhook reached andabot for this push." and "Restarted by the 15-minute sweep: the earlier review stopped without finishing."
- Give-up check run: conclusion `neutral`, title "Review didn't finish", text "The review of `<short sha>` stopped twice without finishing. Comment `@andabot review` to try again." (`@andabot` is the bot login from `BOT_LOGIN`).
- Logs: `sweep.found` (`repo`, `number`, `head`, `reason`: `unreviewed` | `restarted` | `gave_up`), `sweep.done` (`installations`, `repositories`, `pulls`, `found`, `ms`), `sweep.failed` (`installation` or `repo`, `error`).
- Lint: no comments, no assertions but `as const`, complexity ≤ 10, anti-slop rules, no `vi.mock`.
- Parse every GitHub response with TypeBox and `Value.Check`.

## Review Focus

- A repository listing that throws (a 404 after the App lost access) must not stop the other repositories or installations: `sweep.failed`, then go on. Pinned in Task 2.
- Paging stops at the first pull request outside the window, not after reading every open pull request of a busy repository. Pinned in Task 1.
- A decided head whose facts changed (draft → ready) goes through the full path, but one whose facts match costs zero GitHub reads. Pinned in Task 3.
- A sweep restart must keep the pending's `checkRunId` and change its operation id; a second dead finding must give up rather than restart again. Pinned in Task 3.
- `@andabot full review` on a decided head must review it, not answer `known`. Pinned in Task 3 (`decideSweep` is never consulted for a non-sweep incoming) and wired in Task 6.

### Task 3: The object's sweep decision

**Files:**
- Create: `src/review/sweep-decision.ts`
- Modify: `src/review/delivery.ts` (the `sweep` field on the review incoming), `src/review/flight.ts` (`StoredPending` gains `sweepRestarted?: boolean` and `sweep?: "started" | "restarted"`)
- Test: `test/sweep-decision.test.ts`, `test/delivery.test.ts`

**Interfaces:**
- Produces:
  - `export const SweepFacts = Type.Object({ draft: Type.Boolean(), baseRef: Type.String(), title: Type.String() })`. The review variant of `StoredIncoming` gains `sweep: Type.Optional(SweepFacts)`.
  - `export type SweepIncoming = ReviewIncoming & { sweep: SweepFacts }`
  - `export const DecidedReason`, a union of literals: `auto`, `draft`, `base_branch`, `title_keyword`, `path_filters`, `failed`, `unposted`, `unchanged`, `gave_up`.
  - `export const StoredDecided = Type.Object({ headSha: Type.String(), reason: DecidedReason, facts: Type.Optional(SweepFacts) })`. The facts are present for a settings skip, which always has the pull request in hand. An exit that only holds the pending (#118's abandon) stores none, and its head then matches on the sha alone.
  - `export type SweepOutcome = { kind: "reviewed" } | { kind: "restarted" } | { kind: "gave_up" } | { kind: "known"; reason: string }`
  - `export interface SweepState { paused: boolean; posted: boolean; decided: StoredDecided | undefined; pending: PendingReview | undefined; running: boolean; now: number }`
  - `export type SweepDecision = { kind: "known"; reason: string } | { kind: "review" } | { kind: "restart"; previous: PendingReview } | { kind: "give_up"; previous: PendingReview }`
  - `export function decideSweep(state: SweepState, incoming: SweepIncoming): SweepDecision`
  - `export const STUCK_MS = 1_800_000`
  - `export function restartedPending(previous: PendingReview, headSha: string, now: number): PendingReview`: `operationId: "review:sweep:<sha>:restart"`, `deliveryId: "sweep:<sha>:restart"`, `started: now`, `sweepRestarted: true`, `sweep: "restarted"`, and the `checkRunId` kept.
  - `export function decidedRecord(headSha: string, reason: DecidedReason, facts: SweepFacts | undefined): StoredDecided`

- [ ] **Step 1: Write the failing tests:**
  - paused → `known: paused`.
  - posted → `known: already_reviewed`.
  - decided with the same head and facts → `known: <reason>`. A different `draft`, `baseRef` or `title` → `review`. Decided with no stored facts and the same head → `known: <reason>`. A decided record for another head → `review`.
  - pending for another head → `review`.
  - pending for this head that is running → `known: in_progress`, even past 30 minutes.
  - pending for this head, not running, started 29 minutes ago → `known: in_progress`.
  - pending at 30 minutes, not running, unmarked → `restart`.
  - pending at 30 minutes, marked `sweepRestarted` → `give_up`.
  - nothing stored → `review`.
  - `restartedPending` keeps `checkRunId` and changes `operationId` and `deliveryId`.
  - `delivery.test.ts`: a stored review incoming with `sweep` round-trips through `Value.Check(StoredIncoming, …)`, and one without it still checks.
- [ ] **Step 2:** Run `pnpm vitest run test/sweep-decision.test.ts test/delivery.test.ts`. Expected: FAIL.
- [ ] **Step 3:** Implement. Order of the checks: paused, posted, decided, pending. Keep `decideSweep` at or under complexity 10 by giving the pending case its own function.

### Task 6: The object's sweep RPC

**Files:**
- Modify: `src/pull-request.ts`

**Interfaces:**
- Consumes: Tasks 3, 4 and 5.
- Produces: `async sweep(incoming: SweepIncoming, version?: Version): Promise<SweepOutcome>`, a public RPC method beside `accept`.

- [ ] **Step 1:** Implement `sweep`:
  - Build `SweepState` from storage: `isPaused`, `posted:<headSha>`, `decided`, `readPending`, and `operationsOf(pending).length > 0`, with `now = Date.now()`. Make no GitHub call before deciding.
  - Act on the decision:
    - `known`: return it.
    - `review`: store the incoming as `accept` does (`delivery:<id>:review`), run `handle` under `waitUntil` exactly as `accept` does, and return `reviewed`.
    - `restart`: put `restartedPending(...)`, then run the review under `waitUntil` through the resume path (`runReview` with the pending's `checkRunId`), and return `restarted`.
    - `give_up`: `completeCheckRun(previous.checkRunId, previous, gaveUpCheckRun(...))` when there is a run, release the pending, `recordDecided(head, "gave_up")` with the incoming's facts, and return `gave_up`.
- [ ] **Step 2:** A review the sweep starts writes `sweep: "started"` on its new pending, when `incoming.sweep` is set and the flight is `start`. Pass `pending.sweep` through to `renderSummaryComment`, and append the same line to the posted check run's summary.
- [ ] **Step 3:** Run `pnpm check > <workspace>/t6.log 2>&1; tail -20 <workspace>/t6.log`. Expected: pass.
