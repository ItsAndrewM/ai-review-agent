# Re-evaluating Approval Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** andabot approves a head it reviewed once its blocking threads are resolved and the head's other checks pass, without a push, and never approves a failing or unfinished head.

**Architecture:** A pure module, `src/review/approval.ts`, holds the decision, the checks' state and the `last_review` record. The router turns `pull_request_review_thread` and finished `check_suite` events into an `approval` incoming. The object's `evaluateApproval` reads the state live, decides, and submits the approval. `publishReview` records `last_review`, holds a clean review's approval until the checks pass, counts open blocking threads in every mode, and evaluates after itself.

**Tech Stack:** TypeScript on Cloudflare Workers and Durable Objects, TypeBox, vitest, the GitHub REST and GraphQL APIs.

**Spec:** `docs/superpowers/specs/2026-10-20-approval-design.md`

## Review Focus

1. **A finished suite whose `app` is `null` or has no `slug`.** It is another app's suite, so it is routed, and the payload still passes `WebhookPayload`. Test in Task 6.
2. **A conclusion GitHub's docs don't list,** such as `stale` or `startup_failure`. It parses, and it counts as failing. Tests in Task 1 and Task 2.
3. **A summary an earlier approval already rewrote, or an unposted review's summary.** The rewrite replaces the earlier approval's verdict, and leaves an unposted summary alone. Test in Task 3.
4. **A check run with no App** (`app: null`). It counts as another app's run; only andabot's is skipped. Test in Task 2.
5. **One head in two pull requests.** A finished suite lists both, and each gets its own evaluation. Test in Task 6.

  - `type WebhookTrigger = "thread_resolved" | "thread_unresolved" | "checks_completed"` and `type ApprovalTrigger = WebhookTrigger | "review"`

  - `type ApprovalDecision = { kind: "approve" } | { kind: "wait"; reason: DecidedWait }`
  - `interface ApprovalState { workflow: boolean; paused: boolean; open: boolean; reviewInFlight: boolean; headSha: string; reviewedHead: string | undefined; lastReview: LastReview | undefined; openBlocking: number | "unknown"; checks: ChecksState }`
  - `decideApproval(state: ApprovalState): ApprovalDecision`: the first reason that holds, else `approve`. Split it into gate functions, such as the pull request's, the record's and the live state's, each returning `DecidedWait | undefined`, to stay under complexity 10.
  - `awaitsApproval(last: LastReview): boolean`: true when `heldBack` is 0 and the event is `REQUEST_CHANGES`, or is `COMMENT` with an `approve` verdict. `review_stands` is its negation, checked after `approved`.
  - `checksState(runs: readonly CheckRunSummary[], botLogin: string): Exclude<ChecksState, "unknown">`: it skips runs whose `app` is `botLogin`. `failing` when a remaining run's status is `completed` and its conclusion isn't `success`, `neutral` or `skipped`; else `pending` when one isn't `completed`; else `passing`.
  - `openBlockingIn(plan: ThreadPlan | undefined): number | "unknown"`: `unknown` without a plan, else the count of `plan.open` with `blocking`.
  - `interface ReviewFacts { reviewId: number; event: ReviewEvent; headSha: string; verdict: ReviewSubmissionInput["verdict"]; rejected: readonly Rejected[]; at: number }` and `lastReviewOf(facts: ReviewFacts): LastReview`, with `heldBack` the count of `rejected` that `holdsApprovalBack`.
  - `evaluatesAfterReview(event: ReviewEvent, accepted: readonly FindingInput[]): boolean`: false for `APPROVE`, and false when `accepted` has a blocking finding; true otherwise.

### Task 4: evaluateApproval on the object

  1. Fetch the pull request with `(await this.github()).getPullRequest(key, key.number)`, not `freshPullRequest()`, so a review in flight keeps its cached files.
  2. Build the `ApprovalState`. `workflow` is `this.env.REQUEST_CHANGES_WORKFLOW === "true"`. `open` is `state === "open"` and not `draft`. `reviewInFlight` is `(await this.readPending()) !== undefined`. `reviewedHead` is `(await this.readReviewed())?.headSha`. `openBlocking` is `openBlockingIn(await this.threadPlan(pr, "fresh", new Map(), []))`. `checks` comes from a new `checksOn(sha)`, which returns `checksState(runs, this.botLogin())` or, on an error, logs `approval.checks_failed` and returns `"unknown"`.

"", head)`, and `updateIssueComment` when the result is defined. Any error is logged as `approval.summary_failed` and goes no further.
